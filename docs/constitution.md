# SDVC 웹서비스 — Codex 전환 헌장 초안

작성일: 2026-09-18 · 상태: 사용자 요구 및 명확화 답변 반영, Plan과 함께 검토

## 역할 용어

- **수강생**: 웹서비스에서 프로젝트를 만들고 OpenAI API 키를 등록해 사용하는 최종 사용자. 기존 DB와 코드의 `developer` 역할은 호환성을 위해 유지하되 제품 화면과 새 문서에서는 “수강생”으로 표시한다.
- **개발자/운영관리자**: SDVC 웹서비스를 개발·운영하며 수강생 현황과 차단 기능을 사용하는 사람. 기존 DB 역할은 `admin`이고, `admin_tier`로 권한을 세분화한다.
- 기존 `developer` 값을 `admin` 의미로 재해석하거나 일괄 변경하지 않는다. 모든 관리자 기능은 `role=admin`을 서버에서 확인한다.

## 제품의 성립 조건

1. 수강생은 브라우저 로그인 후 본인 OpenAI API 키를 등록해 사용한다. CLI·확장 프로그램·개발 환경 설치를 요구하지 않는다. 최초의 '로그인만' 조건은 사용자 명확화에 따라 키 등록 1단계를 포함하도록 변경됐다.
2. 서버가 헌장 → 명세 → 명확화 → 계획 → 작업 분해 → 분석 → TDD 구현의 순서와 상태를 보관한다.
3. 계획과 작업 분해는 사용자에게 실제 문서를 보여주고 명시적 승인을 받아야 진행한다.
4. 승인한 문서 버전, 구현 작업, 테스트 증거, 배포 버전을 연결한다. 승인 후 문서가 바뀌면 영향받는 승인은 다시 받아야 한다.
5. 완성된 결과물은 고유 URL로 열람할 수 있어야 한다. 저장 성공만으로 배포·완성을 선언하지 않는다.
6. 사용자가 `작업휴식`을 입력하면 진행 문서·미커밋 변경·다음 작업을 프로젝트 내부 체크포인트에 저장하고 검증한다. 다음 세션의 `SDVC 작동`은 그 체크포인트를 먼저 읽어 이어간다.
7. 수강생용 서비스 접근은 인증된 계정에 한정한다. 개발자는 별도의 관리자 권한으로 수강생별 이용 현황을 확인하고, 악성·정책 위반 수강생의 이용을 차단·해제할 수 있어야 한다.

## 개발·실행 원칙

- 플랫폼 개발과 수강생 프로젝트 생성 모두 테스트 선행, 실패 확인, 최소 구현, 정리 후 재검증을 적용한다.
- 테스트 실행 명령·종료 코드·실제 로그·대상 버전을 기록한다. AI가 작성한 성공 문장은 실행 증거로 인정하지 않는다.
- 문서·대화·작업 상태를 영속 저장하고 브라우저 재접속 후 이어간다.
- API 비밀키는 서버에서 관리하며 코드·로그·브라우저에 노출하지 않는다.
- 생성 코드는 신뢰하지 않는다. 운영 서비스·다른 사용자 데이터·관리자 자격 증명과 격리해 실행한다.
- 소유권 확인, 중복 요청 방지, 사용량 한도, 실패 복구를 서버에서 보장한다.
- 수강생 차단 상태는 모든 보호 API와 장시간 실행 시작·재개 지점에서 서버가 확인한다. 차단·해제는 관리자만 수행하고 사유·수행자·시각을 감사 기록으로 남긴다.
- 기능별 RED → GREEN → REFACTOR 및 검증 결과를 커밋과 진행 기록으로 남긴다.
- 체크포인트는 `.sdvc/session-checkpoint/`에 로컬로 유지한다. 비밀값과 의존성·빌드 산출물은 저장하지 않으며, 재개 시 현재 작업 파일을 자동 덮어쓰지 않는다.
- 위 체크포인트는 SDVC 플랫폼 개발자의 로컬 개발 세션 연속성 장치다. 수강생의 웹서비스 재접속·작업 재개는 Supabase의 문서·승인·실행 상태로 제공하며 로컬 Git 체크포인트를 노출하지 않는다.

## 사용자 명확화 결정 (2026-09-18)

- 개발과 서비스 내부 AI 모두 Codex/OpenAI로 전환한다.
- 생성 대상에 자체 서버·DB가 있는 웹앱을 포함한다.
- 수강생이 자신의 OpenAI API 키를 등록한다. 운영자 키로 조용히 대체하지 않는다.
- 수강생 로그인 화면, 개발자용 이용현황 대시보드, 관리자 차단·해제 기능을 필수 범위에 포함한다.

이 문서는 기존 pinusian/sdvc의 승인 이력을 새 구현의 승인으로 간주하지 않는다.

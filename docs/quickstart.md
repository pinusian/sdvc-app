# 완성 후 확인할 대표 사용자 시나리오

상태: 계획 검토용. 아직 실행 가능한 새 구현이나 배포 URL은 없다.

1. 브라우저로 SDVC 서비스에 접속해 가입·로그인한다.
2. 설정에서 본인 OpenAI API 키를 등록한다. 설치는 하지 않는다. API 사용료가 본인에게 발생함을 확인한다.
3. '방문자가 로그인해서 자기 독서 기록을 저장하는 웹앱을 만들어줘'라고 요청한다.
4. 헌장과 명세를 읽고 명확화 질문에 답한다.
5. 생성할 화면·서버 API·DB·검증 방법이 담긴 계획을 승인한다.
6. 기능별 작업 목록을 읽고 승인한다. 승인 전에는 구현을 시작할 수 없어야 한다.
7. 실패 테스트, 구현 후 성공, 정리 후 재검증 기록을 확인한다. 브라우저를 닫았다 다시 열어도 같은 작업이 보여야 한다.
8. 발행 완료 후 고유 URL을 새 브라우저에서 연다.
9. 생성 앱에서 방문자 A로 가입·로그인해 기록을 저장한다. 새로고침과 재로그인 후에도 기록이 남아야 한다.
10. 방문자 B는 A의 비공개 기록을 볼 수 없어야 한다. 다른 생성 앱과 SDVC 관리 데이터에도 접근할 수 없어야 한다.
11. 수정 요청을 하고 새 검증·배포 버전을 확인한다. 새 배포가 실패하면 이전 정상 URL이 유지돼야 한다.
12. 일반 수강생 계정으로 관리자 URL과 API에 접근하면 거부돼야 한다.
13. 개발자 계정으로 관리자 화면에 로그인해 수강생별 가입일·최근 이용·프로젝트·실행·사용량·차단 상태를 확인한다.
14. 시험 수강생을 사유와 함께 차단한다. 그 수강생의 기존 로그인 세션과 직접 API 요청에서도 새 AI 실행·프로젝트 변경·작업 재개가 거부돼야 한다.
15. 관리자 화면에서 차단 감사 기록을 확인하고 수강생을 해제한다. 해제 후 정상 권한으로 다시 이용할 수 있어야 한다.

## 개발 실행과 실제 연동의 구분

플랫폼 개발 실행은 기존 npm install / npm run dev 구조를 활용할 예정이다. 아직 의존성을 설치하거나 새 흐름을 실행하지 않았다. 모의 공급자 시험과 실제 OpenAI·Sandbox·Supabase·Vercel 연동 검증은 구분해서 보고한다.

최종 인수에는 사용자 API 키와 별도 시험 인프라 설정이 필요하다. 키 원문은 채팅에 붙여넣지 않고 완성된 설정 화면이나 지정된 비밀 환경변수에 직접 입력한다.

# SDVC 웹서비스 — 요구 명세 초안

작성일: 2026-09-18 · 최종 갱신: 2026-09-19 · 상태: Plan·Tasks 승인 완료, 구현 진행

## 제품 정의

브라우저 로그인 후 본인 OpenAI API 키를 등록하고, 아무것도 설치하지 않고 SDVC 방법론을 AI와 함께 진행해 자체 서버·DB를 포함한 프로젝트를 만들고, 완성된 결과물을 고유 URL로 열람하는 웹서비스. 키 등록은 후속 명확화에서 사용자가 선택한 추가 단계다.

## 역할 용어와 기존 데이터 호환

- 문서와 화면의 **수강생**은 기존 DB/코드의 `profiles.role = 'developer'`에 해당한다. 기존 데이터와 권한 코드를 보호하기 위해 첫 버전에서는 DB 값을 바꾸지 않는다.
- 문서와 화면의 **개발자/운영관리자**는 기존 DB의 `profiles.role = 'admin'`에 해당한다. 관리자 기능은 `admin_tier`와 서버 권한 검사를 함께 적용한다.
- “개발자”라는 자연어만으로 관리자 권한을 부여하지 않으며, 일반 수강생은 기존 `developer` 값 때문에 관리자 화면에 접근할 수 없다.

## 사용자 이야기

- US-01 / P1: 수강생으로서 로그인 후 만들고 싶은 것을 설명하고, 헌장과 명세를 검토하고 싶다.
- US-02 / P1: 질문과 예시 답안으로 불명확한 요구를 정리하고, 계획과 작업 목록을 확인·승인하고 싶다.
- US-03 / P1: 승인한 문서를 근거로 AI가 테스트와 코드를 만들고, 실제 실행 결과를 확인하고 싶다.
- US-04 / P1: 검증된 결과물을 고유 URL로 열고 공유하고 싶다.
- US-05 / P1: 브라우저를 닫아도 문서·승인·진행 상태를 이어가고 싶다.
- US-06 / P2: 수정 요청을 문서 변경 및 버전으로 추적하고 이전 정상 버전으로 돌아가고 싶다.
- US-07 / P1: 수강생으로서 로그인 화면에서 인증한 뒤 내 프로젝트와 이용 내역만 안전하게 사용하고 싶다.
- US-08 / P1: 개발자로서 관리자 화면에서 수강생별 가입 상태·최근 이용·AI 실행량·프로젝트 현황·차단 상태를 보고 싶다.
- US-09 / P1: 개발자로서 악성 또는 정책 위반 수강생을 사유와 함께 차단하고, 필요하면 감사 기록을 남긴 채 해제하고 싶다.

## 기능 요구사항

- FR-001: 브라우저 회원가입·로그인을 제공한다. 수강생 PC에 개발 도구 설치를 요구하지 않는다.
- FR-002: 서버가 프로젝트 소유자와 현재 SDVC 단계를 검증한다. 클라이언트의 단계 값이나 AI 문구로 건너뛸 수 없다.
- FR-003: 헌장·명세·명확화 답변·계획·작업 목록을 독립적인 버전 문서로 저장하고 열람할 수 있게 한다.
- FR-004: 계획·작업 목록 승인을 문서 버전과 승인자에 결부한다. 미승인·오래된 승인·중복 승인을 차단한다.
- FR-005: 문서 간 일관성을 구현 전에 분석한다. 수정이 필요하면 변경안을 검토받는다.
- FR-006: 생성 프로젝트마다 격리된 실행 환경에서 RED → GREEN → REFACTOR를 수행한다.
- FR-007: 실행 증거에는 작업 ID, 코드 버전, 명령, 시각, 종료 코드, 로그를 포함한다. 실행하지 못하면 미검증으로 표시한다.
- FR-008: 검증된 버전만 완성 상태로 발행한다. URL 접근 및 대표 사용자 시나리오를 확인한다.
- FR-009: 공개 범위와 프로젝트별 고유 URL을 제공한다. 생성 콘텐츠는 관리 화면의 인증 권한과 격리한다.
- FR-010: 장시간 작업은 요청 연결과 분리하고, 상태 조회·재접속·취소·중복 실행 방지를 지원한다.
- FR-011: 수강생이 본인 OpenAI API 키를 등록·교체·삭제한다. 암호화해 서버에 저장하고 원문을 다시 반환하지 않는다. 키 누락·만료·한도 초과 시 명확한 오류를 제공하고 운영자 키로 대체하지 않는다. 사용자별 사용량과 한도를 서버에서 확인한다.
- FR-012: 문서·대화·파일·테스트 로그·배포 버전을 보관하고 이어서 작업할 수 있게 한다.
- FR-013: 배포 실패 시 기존 정상 URL을 유지한다. 실패를 성공으로 표시하지 않는다.
- FR-014: 기존 Claude 서비스의 계정·결제·방문자 기능은 재사용 여부를 검토하되 기존 운영 데이터를 변경하지 않고 검증한다.
- FR-015: 생성 웹앱은 실제 서버 API와 프로젝트 전용 영속 DB를 가진다. 플랫폼 내부의 고정된 records API나 localStorage만으로 대체하지 않는다.
- FR-016: 생성 웹앱은 방문자 인증·자기 데이터 CRUD를 지원하는 참조 시나리오로 검증한다. 방문자와 SDVC 수강생 계정은 구분한다.
- FR-017: 생성한 DB 마이그레이션은 테스트 DB에서 먼저 실행한다. 운영 데이터 삭제·호환성이 깨지는 변경은 변경 영향과 복구 수단을 보여준 뒤 별도 명시적 결정을 받는다.
- FR-018: 플랫폼 개발 과정에서 개발자가 `작업휴식`을 입력하면 현재 단계, 다음 작업, 결정 대기, Git 상태, 진행 문서와 변경 중인 텍스트 파일, working/staged patch 및 파일 해시를 로컬 프로젝트 내부 임시 저장소에 남긴다. 이는 수강생용 웹 기능이 아니다.
- FR-019: 플랫폼 개발의 새 Codex 세션에서 `SDVC 작동`을 입력하면 로컬 임시 저장소의 manifest와 파일 사본을 먼저 읽고 무결성을 검사한 뒤 개발 작업을 재개한다. 수강생의 브라우저 재접속은 FR-010·FR-012의 DB 상태 복원으로 처리한다.
- FR-020: 수강생용 로그인 화면을 제공하며, 인증되지 않은 사용자는 프로젝트·문서·AI 실행·결과물 관리 화면과 보호 API를 사용할 수 없다.
- FR-021: 개발자용 관리자 화면은 관리자 권한을 서버에서 검증하고 수강생별 가입일, 최근 이용 시각, 프로젝트 수, 실행 수·상태, 사용량, 차단 상태를 조회한다. 일반 수강생은 이 화면과 API에 접근할 수 없다.
- FR-022: 관리자는 수강생을 사유와 함께 차단하거나 해제할 수 있다. 차단 시 신규 로그인 세션의 서비스 이용, 보호 API, AI 호출, 새 작업 시작 및 장시간 작업 재개를 서버에서 거부한다.
- FR-023: 차단은 기존 데이터나 결제·사용량 기록을 삭제하지 않는다. 차단·해제 작업은 대상 사용자, 수행 관리자, 사유, 시각, 이전·이후 상태를 감사 기록으로 보존한다.
- FR-024: 차단 직전에 시작된 작업은 안전한 취소 또는 중단 상태로 전환하고, 중복 요청·직접 API 호출·오래된 세션 토큰으로 차단을 우회할 수 없어야 한다.

## 성공 기준

- SC-001: 새 수강생 계정이 개발 도구 설치 0회로 로그인 → 본인 API 키 등록 → 문서 작성 → 승인 → 생성 → URL 열람 시나리오를 완료한다.
- SC-002: 단계 건너뛰기·미승인 구현·승인 버전 불일치 요청이 모두 서버에서 거부된다.
- SC-003: 대표 생성 프로젝트 1개 이상에 대해 의미 있는 RED 실패와 동일 테스트의 GREEN 성공 및 정리 후 재실행 증거가 남는다.
- SC-004: 실패·미검증 버전은 완성으로 발행되지 않는다.
- SC-005: 공개 결과물을 별도 비로그인 브라우저에서 열어 대표 동작을 확인한다. 비공개 결과물은 타인이 열 수 없다.
- SC-006: 재접속 후 같은 문서·승인·작업 상태가 복원된다.
- SC-007: 다른 사용자 프로젝트 접근과 생성 코드의 운영자 비밀키 접근을 차단하는 검증을 통과한다.
- SC-008: 생성된 웹앱에서 방문자 A가 서버 API로 기록을 저장한 뒤 새로고침·재로그인해도 데이터가 남는다. 방문자 B는 A의 비공개 기록을 조회·수정할 수 없다.
- SC-009: 생성 앱 두 개 사이의 DB 접근과 플랫폼 관리 데이터 접근이 거부된다.
- SC-010: API 키 원문이 응답·생성 파일·로그에 없고, 삭제 후 신규 AI 호출이 거부된다.
- SC-011: 플랫폼 개발자가 미커밋 변경이 있는 상태에서 `작업휴식` 후 새 Codex 세션에서 `SDVC 작동`을 실행하면 단계·다음 작업·진행 파일이 복원 가능한 상태로 확인되고, 체크포인트 해시 불일치가 탐지된다. 수강생 재접속 검증은 SC-006으로 별도 판정한다.
- SC-012: 비로그인 사용자의 보호 화면·API 접근과 일반 수강생의 관리자 화면·API 접근이 모두 거부된다.
- SC-013: 관리자가 수강생을 차단하면 기존 세션과 직접 API 요청에서도 새 AI 실행·프로젝트 변경·작업 재개가 거부되고, 해제 후 정상 권한이 복원된다.
- SC-014: 관리자 대시보드의 수강생별 프로젝트·실행·사용량 집계가 원천 데이터와 일치하고, 차단·해제 감사 기록이 누락 없이 조회된다.

## 범위·가정

- Supabase와 Vercel 사용은 사용자 허용 사항이다. 최종 실행 환경과 배포 구조는 Plan에서 확정한다.
- 확정 범위: 홈페이지 및 자체 서버·DB를 가진 웹앱, Codex/OpenAI, 사용자 API 키 등록.
- 생성 스택은 첫 버전에서 Next.js/TypeScript 서버 API와 Supabase Postgres/Auth로 표준화하는 계획을 제안한다. 임의 언어·상시 실행 서버까지 지원하는 의미는 아니다.
- 결제 체계 확장, 커스텀 도메인, 네이티브 앱은 이번 범위에 자동 포함하지 않는다.
- 기존 코드의 테스트 파일 존재는 테스트 통과나 운영 검증을 의미하지 않는다.
